# QA 专家 — 后端代码质量审查

> 状态: PENDING
> 更新时间: 2026-06-03T23:49

## 背景
Phase 1 后端代码已提交，需要严格审查代码质量，找出所有未达到生产级别的问题。

## 审查范围
`backend/` 目录下所有 .go 文件

## 审查清单

### 1. 空实现 / TODO / 占位
- 函数体为空或仅 return nil
- 包含 TODO / FIXME / HACK 注释
- handler 注册了但实现不完整
- Mock 标记的代码是否合理

### 2. 前后端契约对齐
- API 路由路径与 docs/prd/08-api.md 定义是否一致
- Request/Response 字段名与 PRD 定义是否匹配
- 错误码是否与 PRD 定义一致（40001/40101/40301/50001）

### 3. 分层规范违反
- handler 中是否有业务逻辑（应在 service）
- repository 中是否有跨表业务判断
- 是否存在层级跳跃（api 直接调 repository）

### 4. 安全问题
- 密码是否加密存储（bcrypt）
- 手机号是否脱敏返回
- SQL 是否参数化（无字符串拼接）
- JWT secret 是否硬编码在代码中

### 5. 错误处理
- 是否有裸 `err` 返回（未包装为业务错误码）
- 是否有 panic
- 是否有 fmt.Println 调试输出

### 6. 测试质量
- 测试是否覆盖错误路径
- 是否有断言（不只是运行不报错）
- 测试是否独立（无顺序依赖）

### 7. 数据库迁移
- 字段类型是否与 PRD model 定义一致
- 索引是否按 PRD 创建
- 是否有漏建的表

## 输出格式
写入 `.commander/status/qa.md`，格式：

```markdown
# 代码审查报告

> 结论: PASS | FAIL（N个问题）

## 问题清单
| # | 文件 | 行号 | 严重程度 | 问题描述 | 建议修复 |
|---|------|------|----------|----------|----------|
```

严重程度：🔴 高（必须修）| 🟡 中（应该修）| 🟢 低（建议修）
