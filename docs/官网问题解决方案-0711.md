## 2. 后台 > 管理员：RBAC 权限体系 【P0 安全问题】

### 2A) 超级管理员登录失败

**根因**：`AdminLogin()` 中 `user.Role != "admin"` 硬编码检查，`super_admin` 角色被拒绝。

**修复**：`backend/internal/service/auth.go:210`

```go
// 将：
if user.Role != "admin" {
// 改为：
if !isAdminRole(user.Role) {

// 新增辅助函数：
func isAdminRole(role string) bool {
    switch role {
    case "super_admin", "admin", "operator", "support":
        return true
    }
    return false
}
```

### 2B) 后端 RBAC 中间件（当前完全缺失）

**现状危险**：`/admin/*` 路由仅用 `JWTAuth` 校验 token 有效性，**不检查用户角色**。任何注册用户的 JWT 都能调用后台接口。

**修复方案**：新增 `AdminRBAC` 中间件：

```go
// backend/internal/middleware/rbac.go

// AdminRequired 校验用户必须是管理类角色
func AdminRequired(db *gorm.DB) gin.HandlerFunc {
    return func(c *gin.Context) {
        userID := c.GetInt64("user_id")
        var user model.User
        if err := db.Select("role").First(&user, userID).Error; err != nil {
            response.Error(c, errcode.ErrForbidden)
            c.Abort()
            return
        }
        if !isAdminRole(user.Role) {
            response.Error(c, errcode.ErrForbidden)
            c.Abort()
            return
        }
        c.Set("admin_role", user.Role)
        c.Next()
    }
}

// RoleRequired 校验用户角色在允许列表中
func RoleRequired(roles ...string) gin.HandlerFunc {
    allowed := make(map[string]bool, len(roles))
    for _, r := range roles {
        allowed[r] = true
    }
    return func(c *gin.Context) {
        role, _ := c.Get("admin_role")
        if role == "super_admin" {
            c.Next() // 超管通行
            return
        }
        if !allowed[role.(string)] {
            response.Error(c, errcode.ErrForbidden)
            c.Abort()
            return
        }
        c.Next()
    }
}
```

**路由分组应用**：

```go
// router.go
admin := v1.Group("/admin")
admin.Use(middleware.JWTAuth(jwtSecret))
admin.Use(middleware.AdminRequired(db))
{
    // 所有管理员可访问
    admin.GET("/courses", adminHandler.CourseList)
    // ...

    // 仅 super_admin 可访问
    superOnly := admin.Group("")
    superOnly.Use(middleware.RoleRequired("super_admin"))
    {
        superOnly.GET("/admins", ...)
        superOnly.POST("/admins", ...)
        superOnly.PUT("/admins/:id", ...)
        superOnly.DELETE("/admins/:id", ...)
        superOnly.GET("/settings", ...)
        superOnly.PUT("/settings", ...)
    }

    // 运营+超管
    ops := admin.Group("")
    ops.Use(middleware.RoleRequired("super_admin", "admin", "operator"))
    {
        ops.POST("/courses", ...)
        ops.PUT("/courses/:id", ...)
        // ...
    }

    // 客服+运营+超管
    support := admin.Group("")
    support.Use(middleware.RoleRequired("super_admin", "admin", "operator", "support"))
    {
        support.GET("/tickets", ...)
        support.PUT("/tickets/:id/status", ...)
        // ...
    }
}
```

## 3. 后台 > 订单管理：退款后仍可下载 【P1】

### 3A) 退款成功后需要禁用下载

**根因**：
- `RefundOrder()` 仅修改订单状态为 `refunded`，不删除 `purchases` 记录
- `HasPurchased()` 只查 `purchases` 表是否有记录，不看订单状态
- `purchases` 表没有 `status` 字段（只有 `id, user_id, course_id, order_id, created_at`）

**修复方案**：在 `RefundOrder()` 事务中，针对 `course` 类型订单，按 `order_id` 删除授权记录：

```go
// backend/internal/repository/payment.go - RefundOrder() 事务内
// 在 tx.Model(&model.Order{}).Update("status", "refunded") 之前添加：
if order.Type == "course" {
    tx.Where("order_id = ?", order.ID).Delete(&model.Purchase{})
}
```

**注意**：用 `order_id` 精确删除，不用 `user_id + course_id`，因为用户可能有多笔购买同一课程的有效订单。

**补充测试**：退款后调用 `/courses/:id/download` 应返回 403。

### 3B) 充值记录 "refund" 改为中文

**根因**：前端交易记录页直接显示后端 `type` 字段原值。

**修复**：`frontend/src/app/user/transactions/page.tsx`

```typescript
const typeLabels: Record<string, string> = {
```

## 5. 登录问题 【P1】

### 5A) 用户名登录提示只能用邮箱

**现状**：
- 后端 `Login()` 只调用 `FindByEmail()` 查找用户
- 前端 `input type="email"` 但 placeholder 写 "用户名/邮箱"

**修复（最小改动）**：前端 placeholder 改为 `"邮箱"`，去掉"用户名"误导。

```tsx
// frontend/src/app/login/page.tsx
<input type="email" ... placeholder="邮箱" />
```

### 5B) 登录失败缺少错误提示

**根因**：
1. 前端 catch 中取 `err.response.data.error`，但后端返回格式是 `{code, message}`
2. 后端对所有失败场景返回相同的 "邮箱或密码错误"

**修复**：

前端修正错误信息提取：
```tsx
// frontend/src/app/login/page.tsx - handleSubmit catch
const msg = (err as any)?.response?.data?.message || '登录失败，请检查邮箱和密码';
setError(msg);
```

后端区分错误类型（**注意账号枚举风险**，需配套登录限流）：
```go
// backend/internal/service/auth.go - Login()
user, err := s.userRepo.FindByEmail(ctx, normalizeEmail(req.Email))
if err != nil {
    return nil, errcode.New(40001, "该邮箱未注册，请先注册账号")
}
if err := bcrypt.CompareHashAndPassword(...); err != nil {
    return nil, errcode.New(40001, "密码错误，请重新输入")
}
```

**安全补充**：需对登录接口增加限流（如每个 IP 每分钟最多 10 次失败），防止基于错误信息的邮箱枚举攻击。

### 6B) 工单状态显示"横线" 【P2】

**修复**：`admin/src/pages/ticket/List.tsx:8`

```typescript
// 将：
const statusMap = { pending: '待处理', processing: '处理中', replied: '已回复', closed: '已关闭' }
// 改为：
const statusMap: Record<string, string> = { open: '待处理', processing: '处理中', replied: '已回复', closed: '已关闭' }
const statusColor: Record<string, string> = { open: 'orange', processing: 'blue', replied: 'green', closed: 'default' }
```

### 6C) 工单详情"创建时间"显示不对 【P2】

**根因**：直接显示未格式化的 ISO 时间字符串。

**修复**：`admin/src/pages/ticket/Detail.tsx:67`

```tsx

dayjs(ticket.createdAt).format('YYYY-MM-DD HH:mm:ss')
```

## 8. 浏览器标签图标（favicon）消失 【P1】

**现状**：
- `frontend/public/favicon.svg` 本地文件存在
- `frontend/src/app/layout.tsx:11` 已有 icon metadata
- 生产环境 `https://www.zioran.com/favicon.svg` 返回 404

**根因**：前端部署时 `public/` 目录的静态文件未正确部署到服务器。Next.js standalone 模式下 `public/` 需要单独复制。

**修复**：部署脚本中增加 public 目录复制：

```bash
# 部署时同步 public 目录
scp -r frontend/public/* root@120.26.192.163:/opt/zioran/frontend/public/
```

并确认 nginx 或 Next.js 能正确服务 `/favicon.svg`。如果 Next.js standalone 模式下 public 文件不在默认路径，需在 pm2 启动命令中指定或在 nginx 中添加：

```nginx
location /favicon.svg {
    alias /opt/zioran/frontend/public/favicon.svg;
}
```
